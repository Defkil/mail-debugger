## 1. Canonical mailbox, REST, SMTP, and lifecycle

| Medium   | `apps/server/src/config.ts:16`, `apps/server/src/main.ts:41` | Server usage diagnostics printed untrusted arguments directly, including terminal escape/control sequences. Unit and full/slim process regressions cover C0 and C1 controls.                                                                                                                                                                                                                                     |

REST Host/Origin/token checks execute before routing, and the new encoded-path regression proves encoded spellings cannot reach protected handlers unauthenticated. Download responses preserve source/attachment bytes, cap and escape filenames, force executable MIME types to octet-stream, and carry attachment disposition, sandbox, no-store, and nosniff headers. Static path checks reject Windows backslashes, NULs, malformed encoding, and root escape; the packaged web assets are trusted local files.

All adapters use the same transactional `MailService`, monotonic IDs, filters, and post-commit events. SMTP bounds DATA and drains excess input without retaining further chunks, rechecks capacity when committing, and maps storage/message limits to 452/552. Concurrent delivery, migration rollback/backups, cursor identity, abort/disconnect cleanup, and graceful shutdown are covered. Snapshot persistence is explicitly asynchronous: a crash can lose changes since the last completed snapshot, and the byte limit measures stored content rather than process RSS. These are documented development-server limits, not durability or production-service claims.

## 2. IMAP

| Severity | Location                                     | Finding and resolution                                                                                                                                                                                                                                                                                                                                                                                     |
| -------- | -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| High     | `apps/server/src/imap/pending-work.ts:16`    | ImapKit bounded individual lines/literals but allowed unbounded pipelined commands behind asynchronous FETCH/CHECK and mailbox notifications retaining deleted sources. Fixed in `3405234`: 64 commands/4 MiB input, 1024 notifications, and a separate retained-source budget; exceeding a limit disconnects the session. Tests stall CHECK and exercise command counts/bytes and notification retention. |
| Medium   | `apps/server/src/imap/imap-server.ts:98`     | Incomplete implicit-TLS handshakes had no ImapKit session, so shutdown did not close them within its grace period. Fixed in `3405234`: track all accepted raw sockets, cap raw connections, and destroy remaining sockets on shutdown. The regression leaves a handshake unfinished and checks shutdown.                                                                                                   |
| Medium   | `apps/server/src/imap/imap-server.ts:143`    | STARTTLS inactivity could send a plaintext BYE into a TLS handshake. Fixed in `3405234`: destroy the negotiating socket instead.                                                                                                                                                                                                                                                                           |
| High     | `apps/server/src/imap/output-control.ts:364` | The 1 MiB ENVELOPE/BODYSTRUCTURE estimate cap underestimated arbitrarily large headers/structures before output allocation. Fixed in `3405234`: conservatively charge escaped header/source size. A repeated large-envelope FETCH is refused before output is built.                                                                                                                                       |
| Low      | `apps/server/src/imap/output-control.ts:83`  | A pending drain timer/listener outlived a disconnected socket. Fixed in `3405234`: drain and close both clear the timer and remove both listeners.                                                                                                                                                                                                                                                         |

The restricted INBOX profile is coherent: credentials and TLS gating apply to LOGIN and AUTHENTICATE; capabilities change after STARTTLS; EXAMINE is read-only; FETCH Seen, STORE, subscription, and expunge mutate the canonical mailbox before successful output. Tests exercise UID/sequence distinctions, concurrent REST/SMTP/IMAP changes, IDLE, persistence/migration, protocol errors, literals, flags, unsupported operations, and slow readers with ImapFlow and raw transcripts. Targeted review verification passed 31 IMAP tests, lint, and server typecheck.

Acceptable disclosed limitation: random UIDVALIDITY removes deterministic rapid-restart reuse, but cannot guarantee collision-free or monotonically increasing values across discarded/recreated datasets. [RFC 3501 section 2.3.1.1](https://www.rfc-editor.org/rfc/rfc3501.html#section-2.3.1.1) requires stronger continuity when prior-session UIDs do not persist. This development profile recommends `--data-dir` for persistent cache continuity and makes no complete RFC or desktop-client interoperability claim. Within a retained dataset, UIDVALIDITY/UIDNEXT/flags persist and UIDs are never reused, including after clear; exhaustion refuses new mail.

Svelte escapes displayed email fields. The token stays in tab memory and authenticated requests use headers. The iframe permits same-origin access for resizing but permits no scripts/forms/popups/top navigation, and its first injected meta policy blocks network resources unless images are explicitly approved. Entity-encoded meta refresh was investigated: the regex is not the security boundary; the sandbox's automatic-features flag blocks refresh because `allow-scripts` is absent. This follows the [HTML sandbox rules](https://html.spec.whatwg.org/multipage/browsers.html#sandboxing) and [refresh algorithm](https://html.spec.whatwg.org/multipage/semantics.html#attr-meta-http-equiv-refresh); comments now state the required sandbox assumption.

Browser/UI automation was excluded by the owner's instructions. Verification uses source inspection, pure policy/document tests (17 preview tests), Svelte checks, the emitted build, and HTTP/installed-package checks. No claim of manual browser testing is made.

## 5. Code quality and test evidence

The canonical service prevents separate REST/MCP/IMAP mailbox implementations. IMAP-specific parser/output adaptation is justified by the pinned library's protocol behavior and lacks server-owned unbounded queues after the fixes. The client remains framework-free and validates public wire contracts; protocol adapters use typed library interfaces. Lint exceptions inspected are narrowly explained (terminal-control regexes, the main binary embedding the CLI, library/framework conventions).

New tests target observed failure modes: lock preservation, failed-export retry, partial-file cleanup, frozen-clock identities, encoded authorization paths, client callback cancellation and malformed payloads, escaped MCP result size, IMAP queue/structure bounds, unfinished TLS, bridge closure, terminal diagnostics, and release conflicts. Polling helpers use bounded assertions; tests use ephemeral ports and own temporary directories. Release tests replace npm/fetch before loading the scripts and never publish.

Coverage floors remain enforced, not waived for fixes: server mail 95% lines/branches, DB and API 90% lines/80% branches, IMAP 80% lines/60% branches, MCP tools 95% lines/80% branches; the client and CLI also have floors. Entry-point and transport/process behavior is exercised by E2E and installed-tarball smoke rather than hidden behind `passWithNoTests`. Coverage numbers and final test totals are recorded with the final gate below. The test matrix does not establish exhaustive RFC compliance, manually tested GUI clients, crash-proof persistence, or every real terminal emulator; the docs state these limits.
